These are controller rulings on the approved C0 contract's implementation boundaries, following nine bounded read-only preflight checks. They add no record kind, public function, dependency, permission, runtime or risk threshold. Original approved snapshots remain byte-identical. ## Exact local interpretation

1. **Decimal lexical form and depth.** D is ASCII fixed-point: integer part `0` or a nonzero digit followed by digits, optional fractional part of one or more digits ending nonzero; no leading plus, whitespace, exponent, non-ASCII digits, `.1`, `1.`, leading integer zero, redundant fractional zero or negative zero. Only explicitly signed fields permit minus. Count precision as Decimal coefficient digits after leading zeros, including significant integer trailing zeros, max38; fractional positions max18. Zero is exactly `"0"`. JSON size includes every raw byte. Container nesting counts root object as depth1, each child dict/list adds1, scalars add0; max32. String length uses Unicode code points, with invalid/unpaired surrogate values rejected so canonical UTF-8 encoding is possible. These choose the ordinary meaning of canonical decimal/UTF-8 and fix boundary-test counting, without expanding the approved limits.
2. **UNKNOWN reasons without adding keys.** Literal UNKNOWN is allowed only at an expressly listed U(X) or enum alternative. For exact record shapes with no problems/unknowns member (e.g. inert policy, proposal, approval or book), C0 preserves the allowed marker; it does not add a reason field or pretend it confers permission. The consuming policy/controller/receipt supplies the stable field-path reason when it uses or reports that UNKNOWN. For shapes with an existing problems/unknowns channel, follow that shape's explicit completeness/diagnostic rules. Missing/UNKNOWN submit-required evidence must still deny new risk; no untyped reason is hidden in a source locator.
3. **Cancel permit.** Its allowed_actions is exactly `['request_cancel']`, action exactly request_cancel; expiry uses the independently valid cancel scope. It has no submit sizing, reserve_context or reusable submit privilege. This follows the approved one-requested-action rule, not new cancellation authority.
4. **Pure C0 versus trusted state.** C0 checks shape, canonical values/hashes and same-record relationships only. OrderRef's match to a trusted command, approval truth, actual account ownership/coverage, canonical host/path binding and proof of external reserve overlap belong to L/A/T at their defined trust boundaries. No C0 validator may open a database, resolve a filesystem path, read environment/credentials, call gethostname or consult an API. The approved local gethostname exception is for future L store construction, not C0's pure functions. A structurally valid record is never proof of authorization or source truth.
5. **Reserve overlap and usage.** C0 checks cash identities, nonnegative local/overlap values, overlap<=local_amount, unique listed IDs where required, and obvious numeric totals available in the record. External reservation IDs are opaque; do not silently equate them with exchange_order_id. Per-ID covered amounts and identity mappings require verified external semantics in A/L and the S1 compatibility evidence gate. Missing/unproven mapping stays HOLD, even if a structural record parses. A missing approval_usage row is UNKNOWN; known zero requires an explicit matching row with zero counters/amounts and complete disjoint risk evidence.
6. **Observation coverage and fees.** complete=true requires the whole requested window, has_more=false/to_cursor=null and, for account_all, account_scope_verified=true. has_more=true requires a nonnull next cursor; incomplete output needs a stable problem. Runtime input cursor equality and continuity are verified by the caller using the original request/persistent watermark, not by a context-free parser. FillRow KNOWN fee requires nonnull finite nonnegative fee_amount plus explicit fee_asset/fee_unit; UNKNOWN fee uses null amount and cannot become zero. A verified zero fee is KNOWN `"0"`. Transport acceptance and cancel200 remain observations, not lifecycle confirmation.
7. **Nested scalar/list types.** account_event.fill.side is BUY|SELL; fill.fee_event_ids and settlement_evidence.external_event_ids are list[S]. fee.included_in_cash_delta, settlement fees[].included_in_balance_delta and source_refs[].complete are exact B. Settlement source_refs[].observed_at is T. Use Asset.asset_id per final C0 override, not the older collateral_asset subkey. An arbitrary blockchain identifier is not automatically a canonical record SHA.
8. **Account-event union.** fill is nonnull exactly for FILL; fee is nonnull for FEE (amount may explicitly be UNKNOWN); for other types it is null unless that very event carries independently identified linked fee evidence. Do not invent a second fee-event identity merely to fit a type switch. reservation_change is required for RESERVATION_UPDATE and otherwise nullable; any nonnull value still requires the committed L source version/hash and cannot authorize a caller-controlled release. reverses_event_id is nonnull exactly for REVERSAL. command_id/exchange_order_id are N(S), preserving externally discovered activity; absent linkage/finality requires supporting source evidence and A/L HOLD, never fabricated local ownership. Other nullable transaction/block fields retain the approved exact types. No actual cash/exposure projection is implemented by C0.
9. **Journal hash representation.** payload_sha256 is canonical_sha256(payload). The stored envelope consists of its listed preimage fields plus store-computed event_hash; event_hash hashes the listed preimage without that field. The public store_event has no caller-provided journal version/previous hash/event_hash. C0 may validate the internal RESERVE_ACCEPTED structural variant for persisted data, while rejecting unauthorized public append of it is L's responsibility; the pure validator has no caller-authorization context. No extra top-level record kind is introduced.
10. **Receipt source hashes and empty store.** CommandSummary.approval_sha256 is canonical_sha256(the immutable approval wrapper in permit.reserve_context.approval); the external approval_receipt_sha remains a distinct evidence digest in that wrapper/permit. Never substitute one for the other. intent_sha256 remains original intent evidence or UNKNOWN, distinct from proposal_sha256. A baselined store with zero commands can emit its factual closeout; an unbaselined store with UNKNOWN identity/asset cannot invent account_ref/mode/venue/Asset and build_receipt must raise ValidationError. It may still expose its HOLD store_snapshot. Multi-command receipts preserve all commands/exposure as approved.
11. **Actual cost.** Keep the approved V2 definitions: actual_cost is verified fill gross principal excluding fees; actual_fee is separately deduped; signed actual cash_delta includes fees once. Gross0.18/fee0.01 implies delta-0.19; inclusive-debit linked informational fee must not become-0.20. This note adds no estimates or profit certification.
12. **Test boundary.** C0 fresh-import/function zero-IO checks cover application-origin filesystem/network/environment/credential actions; normal Python code loading and pytest's own temporary fixture/heartbeat setup are not falsely labeled C0 actions. Install tripwires after harness bootstrap and before the C0 import/call; preserve attempts even when exceptions are swallowed. Existing guard import/URL checks are recursive, but the old M2-specific environment/request scan only visits top-level src, and tracked-file secret mode does not cover untracked new files. C0 needs its own checks; V later adds the full recursive proof. No test was run by these nine preflight lanes.
