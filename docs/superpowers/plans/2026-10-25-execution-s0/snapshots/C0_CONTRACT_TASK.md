### Primitive notation and strictness

The following is schema notation in this document, not a new runtime DSL. `S`: nonempty nonsecret string, length <=4096; `H`: 64 lowercase hex; `I`: exact int in [0, 2^63-1], rejecting bool; `B`: exact bool; `T`: UTC RFC3339 string with `Z`, calendar-valid, max six fractional digits; `D`: canonical finite decimal string, <=38 significant digits and <=18 fractional digits, no exponent/leading plus/redundant trailing fractional zero, zero exactly `"0"`; signed only where explicitly stated. `U(X)` allows literal `"UNKNOWN"` with a matching stable problem/unknown reason, never implicit zero. `N(X)` permits JSON null only where listed. Arrays are JSON lists; typed object keys are exact; missing/extra keys reject recursively. Reason codes use `[A-Z][A-Z0-9_]{0,63}`. Size limits: raw JSON <=1MiB, depth <=32, array <=10000, string bound above; exceeding rejects before business logic. Raw UTF-8 BOM, duplicate keys, float JSON tokens, nonfinite constants and invalid UTF-8 reject. Integer tokens remain exact I; decimals must be strings. Hash uses UTF-8 `json.dumps(sort_keys=True,separators=(',', ':'),ensure_ascii=False,allow_nan=False)`, without Unicode normalization; semantic identifiers must match exact bytes.

All top-level kinds have `schema_version:I=1`. Common `Scope` fields are `account_ref:S,venue:S`; `Units` fields are `collateral_asset:U(S),chain_id:U(I),unit_scale:U(I),price_unit:U(S),shares_unit:U(S),money_unit:U(S),money_quantum:U(D)`; quantum positive power of ten. `Asset={chain_id:I,asset_id:S,unit_scale:I}`; asset_id equals the proven collateral_asset for cash. Complete records cannot carry risk-critical UNKNOWN. A record's source/evidence hash binds supplied evidence bytes, not authenticity or Owner approval by itself.

### Store events, snapshots and controller results

**store_event:** `schema_version,event_id:S,event_type,command_id:S,recorded_at:T,payload,payload_sha256:H,source_ref:S`.
