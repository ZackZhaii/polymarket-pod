## Review Focus exact shared wording
RF1 — Submission uncertainty and crash/restart: durable reserve and command precede transport; SUBMITTING recovery is UNKNOWN with no blind resend.
RF2 — Cancel/late-fill/stop races: request is not confirmation, reserve survives unknown remainder, and authorized observe/cancel survives stop-new-orders.
RF3 — Account scope, collateral, fees and cross-run reserve overlap: complete external truth, disjoint reserve accounting, one bound store across run_id, no fresh-DB budget reset.
RF4 — Protocol/schema/time/approval boundaries: exact asset/domain/units, strict finite types and hashes, freshness/expiry; UNKNOWN required inputs deny new risk.
RF5 — Recursive execution boundary, exports and economic evidence: no S0 SDK/network/credentials; secret-safe mode-explicit receipts, no paper/synthetic fill or missing cost promoted to real profit.

## Binding schema/ownership resolutions
1. Store API addition: `ExecutionStore.controller_lock(self) -> ContextManager[None]`. It owns existing StateLock reuse against approved canonical store/controller lock location; controller/safety never access `_db_path`, sqlite connections or private store internals. Store append/reserve use BEGIN IMMEDIATE; no DB transaction spans transport/network. Controller submit/cancel/recover hold this lock only for short durable claim/state-commit phases and release it before any transport/network operation. A committed SUBMISSION_STARTED prevents a second submit while the lock is released. Stop and scoped cancel cannot be blocked behind an in-flight transport by this lock; per-command cancellation claims are also durable and versioned. A submit already durably claimed before stop may be in flight: record uncertainty/observe/cancel, never claim instant prevention or flatten.
2. Exact global control command ID is `__store__`. User command IDs beginning `__` are rejected. Add validated `store_event` kind to C0. append_event('__store__',...) accepts only STOP_SET, ACCOUNT_BASELINED, ACCOUNT_RECONCILED, APPROVAL_REVOKED; command events SUBMISSION_STARTED, SUBMISSION_UNKNOWN, ORDER_OBSERVED, CANCEL_REQUESTED, CANCEL_OBSERVED, UNSENT_REJECTED, EVIDENCE_CONFLICT; RESERVE_ACCEPTED is store-internal only. Store determines state/budget projections from valid events; callers cannot set arbitrary cash or clear stop. No automatic STOP_CLEAR/resume in S0/S1. Event envelope exact schema_version=1,event_id,event_type,command_id,recorded_at,payload,payload_sha256,source_ref; payload schemas map to operation. Stored globalversion/previoushash/eventhash are store-computed, not trusted caller values.
3. Add `store_snapshot` and `controller_result` kinds. Store reserve/append_event/snapshot all return store_snapshot with schema_version,store_id,store_binding,version,state_sha256,new_orders_stopped,stop_reasons,commands,reservations,account,approval_usage,event_refs. account may be explicit UNKNOWN only before validated baseline; new risk denied. `version` exact nonnegative int; state_sha256 is the committed journal head hash with C0-defined genesis/envelope preimages; it is not a recursive snapshot self-hash. Controller public methods all return controller_result with exact schema_version,command_id(str|null),status,store_version,store_state_sha256,reasons(list[str]); recover global command_id=null. Full state is read via snapshot, not a second mutable response authority.
4. One authoritative DB across run_id: runs/execution/execution.sqlite3. Approval binds host_ref, canonical_store_path, store_id and authorized account; store validates canonical binding. New/copy/per-run DB does not inherit approval/caps. Startup requires complete external reconciliation plus known cumulative approval usage, never PAPER_EQUITY or resetting historical loss. Single-host, controlled canonical store is an explicit assumption, not distributed/malicious filesystem protection. Readonly JSONL exports are projections, not import/recovery authority.
5. Permit `reserve_context` embeds immutable validated proposal/account_snapshot/book_snapshot/approval/policy with canonical hash bindings, source_global_version/source_state_sha256, store_binding. Under BEGIN IMMEDIATE reserve revalidates expiry, hashes, current globalversion/statehash, stop latch, cumulative caps and disjoint current local reservations. Hashes alone cannot authorize cash. If external snapshot needs unknown overlap/freshness or previous usage, deny; no zero defaults. This is input evidence, not claim that local SQLite proves remote freshness.
6. Canonical cash fields from accounting lane: cash_total,cash_external_available,cash_external_reserved,cash_local_additional_reserved,cash_reserved,cash_available. cash_reserved=external_reserved+local_additional; cash_available=total-reserved. Asset identity tuple chain_id,asset_id,unit_scale; never sum unlike units. reserve_groups liability_kind OPEN_ORDER|SUBMIT_UNKNOWN|PENDING_DEBIT|PENDING_FEE, with reservation_id/command_id/external_order_id,asset_key,local_amount,external_overlap_amount/source evidence. Groups disjoint, 0<=proven overlap<=local amount; unknown relation HOLD. Do NOT additionally add a top-level unfinalized_fee reserve if already in groups. Alternative draft names local_unrepresented_reserved/local_additional_reserved/unfinalized_fee_reserved are NOT public fields.
7. authorize remains exact locked signature. proposal.action is submit|request_cancel. Submit requires fully reconciled/fresh account+book, complete cost bound, valid submit scope/expiry/neworder permission. Cancel requires bound known_order_ref and independent approval.cancel_scope/cancel_expires_at/allowed action, not submit expiry or submit budget. Stopped/stale/missing cash can still permit scoped cancel if identity/action permission is proven; unknown ownership or cancel approval denies. No cancel grants submit or releases reserve before external confirmation.
8. `receipt` is a tagged union: receipt_type=reconciliation|settlement_validation|execution_closeout. Each subtype has exact field set in C0 table, so do not add a separate unvalidated reconciliation kind. project_account returns account_snapshot. reconcile and validate_settlement_evidence return their receipt subtypes; build_receipt returns execution_closeout. Common receipt header schema_version,receipt_type,receipt_id,generated_at,mode,account_ref,verdict,unknowns,limitations,evidence_refs,authorization_effect='NONE'. Unknown settlement/actual fees remain unknown, partial receipt cannot certify full S1/finality.
9. Transport observations keep operation discriminators submit/cancel/order/open_orders/fills; read_account returns account_snapshot. Submit ACK status ACCEPTED|REJECTED_RESPONSE|UNKNOWN, never FILLED_CONFIRMED from an ACK. Cancel request status CANCEL_REQUESTED|CANCEL_UNKNOWN, never terminal confirmation from HTTP200. Whole account scope/pages/time completeness requires source/coverage evidence, not HTTP success. Canonical signed command amount must equal permitted payload; SDK auto-resize/max_spend behavior cannot silently change it. Heartbeat side effects/account-key-wide cancels require separate API/Owner evidence; never probe authenticated endpoint in S0.
